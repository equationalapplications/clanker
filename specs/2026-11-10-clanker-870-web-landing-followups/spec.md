## Changes

### 1. Dev/prod `/` divergence — document it (docs-only)

Production `/` serves the static landing page (`landing/index.html` copied to
`dist/index.html` by `scripts/finalize-web-export.mjs`); dev
(`expo start --web`) and in-SPA `/` render `app/index.tsx`, which redirects to
`/sign-in`. Accepted per the landing spec, but never written down.

- `docs/superpowers/specs/2026-10-25-web-root-static-landing-design.md`: add a
  short "Dev/prod divergence at `/`" section stating the above and that the
  divergence is accepted.
- `README.md`: one line in the web/deployment context pointing at the same fact.

### 2. `scripts/finalize-web-export.mjs` — `patchShell()` throws instead of exiting

`patchShell()` is exported (marketing tests import it) but calls `fail()` →
`process.exit(1)` on its two guard conditions (`shell has no <title>`,
`shell already carries a robots meta`). If a suite exercises the failure path,
`process.exit` kills the Jest worker outright.

- `patchShell()` throws a plain `Error` with the same messages.
- `main()` wraps its `patchShell(shell)` call in try/catch and maps a caught
  error to `fail(error.message)` — the CLI's loud-fail behavior is unchanged.
- Add a unit test asserting `patchShell()` throws (not exits) on both guard
  paths and returns patched HTML on the happy path. If marketing suites for
  this script already exist, extend them; otherwise add
  `__tests__/finalize-web-export.test.mjs` (or the repo's testable equivalent —
  plan decides the exact location given jest transform rules for `.mjs`).

### 3. CI up-to-date check for `landing/index.html`

`landing/index.html` is tracked AND regenerated by `generate:static-pages` on
every `predeploy`. `generate-static-pages.js` derives the sitemap `/` `lastmod`
from `lastmodFromFile(LANDING_FILE)` — i.e. from git history of the tracked
file. A stale tracked file silently publishes a wrong sitemap date.

- No existing up-to-date CI check was found in `scripts/` or
  `.github/workflows/` (searched 2026-11-10) — this is a fresh check, not a
  mirror of an existing pattern as the issue assumed.
- Shape: a new `npm run check:generated` script that runs
  `generate:static-pages` into a temp/clean state and exits non-zero if
  `git status --porcelain` shows changes under `landing/` (and the other
  generator-written outputs feeding the sitemap: `public/real-time-voice/index.html`,
  `sitemap.xml`). Wire it as a step in `staging-test.yml` (or
  `production-build.yml` — plan picks the cheaper placement that still gates
  every deploy).
- Commit-message hygiene: the check must run BEFORE any `git add`, i.e. it is
  read-only on the tracked tree apart from regenerating outputs which it
  restores/reverts afterward (implementation detail for the plan).

### 4. `requestIdleCallback` shim → shared jest setup

The shim lives in `src/utilities/__tests__/okfSave.test.ts`'s `beforeAll`
(RN 0.88 removed `InteractionManager`; `okfSave.ts` defers native readiness via
`requestIdleCallback`). Any OTHER suite importing `okfSave` —
`src/hooks/__tests__/useExportCharacterOKF.integration.test.ts` already does —
throws unless it defines its own shim.

- Move the shim into the shared jest setup that runs for both the `native` and
  `jsdom` projects (candidate: `jest.setup.js`; plan verifies project wiring in
  `jest.config.js` — the shim is environment-agnostic: a plain
  `global.requestIdleCallback = (cb) => cb()` style polyfill with the same
  semantics the test uses today).
- Delete the `beforeAll` shim from `okfSave.test.ts`.
