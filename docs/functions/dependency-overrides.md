# `functions/` Dependency Overrides

This document tracks every entry in `functions/package.json`'s `overrides`
block and every transitive-vulnerability audit residue in the `functions/`
workspace. Every override carries a tracked rationale and a removal condition.

> **Phase 4 of the dependency-security and major-upgrades effort.** See
> [`docs/superpowers/specs/2026-08-11-dependency-security-and-major-upgrades-design.md`](./../superpowers/specs/2026-08-11-dependency-security-and-major-upgrades-design.md#phase-4--overrides-sweep)
> for the rules this document enforces.

## `uuid: ^11.1.1` — keep

| Field                        | Value                                                                                                                                                                                                                                                                                             |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Status                       | **Active. Required.**                                                                                                                                                                                                                                                                             |
| Advisory                     | [GHSA-w5hq-g745-h8pq](https://github.com/advisories/GHSA-w5hq-g745-h8pq)                                                                                                                                                                                                                          |
| Severity                     | moderate                                                                                                                                                                                                                                                                                          |
| Vulnerable                   | `<11.1.1` (CWE-787, CWE-1285 — buffer bounds check missing in v3/v5/v6)                                                                                                                                                                                                                           |
| Resolution                   | `>=11.1.1`                                                                                                                                                                                                                                                                                        |
| Natural (without override)   | multiple `uuid@9.0.1` instances via `google-gax`, `gaxios`, `teeny-request`, `googleapis`, `gtoken` — all in the vulnerable range                                                                                                                                                                 |
| Why this is not a major bump | `@google/adk@1.6.0` transitively depends on `google-auth-library@^10.3.0`, which constrains the safe `uuid` versions through its `gaxios`/`gtoken` peers. The override forces the whole tree to `>=11.1.1`, while ADK's own `@a2a-js/sdk → uuid@11.1.1` continues to resolve to the safe version. |
| Removal condition            | When `@google/adk` (or any of its transitive `google-*` deps) publishes a version where the whole tree resolves to `uuid@>=11.1.1` without the override — i.e., when the constraint moves to the parent.                                                                                          |

## `sqlite3.tar: 7.5.22` (scoped) — keep

| Field                              | Value                                                                                                                                                                                                                                                             |
| ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Status                             | **Active. Required.**                                                                                                                                                                                                                                             |
| Advisory                           | [GHSA-34x7-hfp2-rc4v](https://github.com/advisories/GHSA-34x7-hfp2-rc4v), [GHSA-8qq5-rm4j-mr97](https://github.com/advisories/GHSA-8qq5-rm4j-mr97), [GHSA-83g3-92jg-28cx](https://github.com/advisories/GHSA-83g3-92jg-28cx) (and follow-ons)                     |
| Severity                           | **critical**                                                                                                                                                                                                                                                      |
| Vulnerable                         | `tar <=7.5.20` — arbitrary file creation / overwrite via hardlink path traversal and symlink poisoning during extraction                                                                                                                                          |
| Resolution                         | `tar >=7.5.21` (latest 7.5.x is `7.5.22`)                                                                                                                                                                                                                         |
| Natural (without override)         | `tar@6.2.1` — vulnerable, via `drizzle-orm@0.45.2 → sqlite3@5.1.7 → node-gyp@8.4.1 → make-fetch-happen@9.1.0 → cacache@15.3.0 → tar@6.2.1` (and direct `sqlite3 → tar`)                                                                                           |
| Why scoped to `sqlite3`            | The vulnerable `tar` instance is reached only through `sqlite3` (native module, in turn pinned by `drizzle-orm`). A scoped override limits the force to that branch and leaves other `tar` consumers (`firebase-tools`, future tooling) on whatever they declare. |
| Why not bumping `drizzle-orm`      | `drizzle-orm@0.45.x` is the current line; `drizzle-orm@1.x` is a breaking major that is out of scope for this effort (separate spec required).                                                                                                                    |
| Why not bumping `sqlite3` directly | `sqlite3@5.1.7` is the latest 5.x. `sqlite3@6.x` is a native-module rebuild; out of scope without its own effort.                                                                                                                                                 |
| Removal condition                  | When `sqlite3` ships a version that bumps its transitive `tar` to `>=7.5.21` natively — i.e., when the fix moves to the parent.                                                                                                                                   |

## Removal conditions

- `uuid: ^11.1.1` — drop when the `google-*` peer chain moves past `uuid@9.0.x`.
- `sqlite3.tar: 7.5.22` — drop when `sqlite3` ships a version that bumps its
  transitive `tar` to `>=7.5.21` natively.
- All accepted-residue rows above resolve when their respective parents
  (mostly `@google/adk`) release a version that bumps the transitive past
  the advisory. None are achievable inside Phase 4 alone.

## How to update this document

1. Re-enumerate: `(cd functions && npm audit --json > /tmp/audit-fn.json)`.
2. For each advisory: identify the immediate parent; check whether the parent
   has a non-downgrade fix; if not, decide between scoped override and
   accepted residue.
3. Update the relevant section above, naming the advisory ID and removal
   condition.
4. If an override is added, write its section in this file **before** the
   `functions/package.json` edit is committed.
