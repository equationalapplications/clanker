# `cloud-agent/` Dependency Overrides

This document tracks every entry in `cloud-agent/package.json`'s `overrides`
block and every transitive-vulnerability audit residue in the `cloud-agent/`
workspace. Every override carries a tracked rationale and a removal condition.

> **Phase 4 of the dependency-security and major-upgrades effort.** See
> [`docs/superpowers/specs/2026-08-11-dependency-security-and-major-upgrades-design.md`](./../superpowers/specs/2026-08-11-dependency-security-and-major-upgrades-design.md#phase-4--overrides-sweep)

## Note: `express` is intentionally NOT tree-wide-forced

Per the spec's Phase 1 rule: `@google/adk@1.6.0` depends on `express@^4.22.1`.
`cloud-agent/` uses `express@^5.2.1` directly. After Phase 1, the tree carries
both `express@5` (direct) and `express@4` (under ADK). This is the intended
state — they are separate instances, ADK does not share a router with the app,
and forcing `express@5` tree-wide via an override would hand ADK a major it was
not built against.

## Removal conditions

- `uuid: ^11.1.1` — drop when every resolved `uuid` in the tree is outside the
  three vulnerable ranges (`<11.1.1`, `>=12.0.0 <12.0.1`, `>=13.0.0 <13.0.1`)
  without the override. Today, the `google-*` peer chain still pulls
  `uuid@9.0.1` (inside `<11.1.1`), so the override is required.
- `sqlite3.tar: 7.5.22` — drop when `sqlite3` ships a version that bumps its
  transitive `tar` to `>=7.5.21` natively.
- All accepted-residue rows above resolve when their respective parents
  (mostly `@google/adk`) release a version that bumps the transitive past
  the advisory. None are achievable inside Phase 4 alone.

## How to update this document

1. Re-enumerate: `(cd cloud-agent && npm audit --json > /tmp/audit-ca.json)`.
2. For each advisory: identify the immediate parent; check whether the parent
   has a non-downgrade fix; if not, decide between scoped override and
   accepted residue.
3. Update the relevant section above, naming the advisory ID and removal
   condition.
4. If an override is added, write its section in this file **before** the
   `cloud-agent/package.json` edit is committed.
